Setup on Kaggle

This page takes you from no accounts at all to a notebook that runs Gemma 2 on Kaggle's free GPUs. Follow the steps in order. Each one says what it does, why it is needed, and what you should see when it worked.

Start early

Two steps involve waiting on someone else: Kaggle's phone verification, and the Gemma license approval. Both are usually quick, but do steps 2 and 4 the day the homework is assigned, not the night before.

  1. What you will end up with

    By the end of this page you will have:

    • A Kaggle account with phone verification, which unlocks free GPUs and Internet access inside notebooks.
    • An OpenRouter API key with a few dollars of credit and a spending limit, stored safely as a Kaggle Secret.
    • Access to Google's Gemma 2 models on Kaggle.
    • Your own copy of the lab notebook, attached to two GPUs and the Gemma 2 model files, which has completed one successful smoke-test run.

    Time: about 45 to 60 minutes of your attention, plus any waiting for verification. The smoke test itself takes about 10 minutes of GPU time. The full 9B run is estimated at 20 to 30 minutes (it has not yet been timed on Kaggle).

    Cost: Kaggle is free. OpenRouter needs a small amount of prepaid credit (a few dollars is plenty for the whole project; see step 3).

    Gemma 2 9B has about 9 billion parameters. Just holding them in memory takes around 18 GB, which is more than a laptop GPU or a single free cloud GPU has. Kaggle offers two 16 GB GPUs for free, which is enough if the model is split across both. That is why we use Kaggle and why several steps below are about getting those GPUs.

  2. Create a Kaggle account and verify your phone

    1. Go to kaggle.com and click Register. Signing up with your Google account is fastest; email also works.
    2. Once you are signed in, click your profile picture (top right), then Settings.
    3. Find the Phone verification section and follow the prompts: enter your phone number, receive a code by text message, and type it in.

    Kaggle gives away GPU time, so it uses phone verification to stop people from creating many accounts to collect more. Until your phone is verified, the GPU accelerators and the Internet switch stay locked in every notebook. The lab notebook needs both: the GPUs to run Gemma, and the Internet to install a few packages and call OpenRouter.

    Your Settings page shows your phone as verified. Later, in a notebook's Session options, the Accelerator menu lists GPU options and the Internet switch can be turned on. If you instead see a message such as "Get phone verified", the verification has not gone through yet.

  3. Get an OpenRouter API key

    First, what is an API key?

    An API (application programming interface) lets one program ask another program, usually on another company's servers, to do something. Our notebook sends text to models run by other companies and gets their replies back. An API key is a long secret string, like sk-or-v1-…, that the notebook sends along with each request to prove it is you. The service then charges the request to your account.

    Treat your key like a password that is attached to your credit

    Anyone who has your key can spend your credit. Never paste the key into a notebook cell, a chat message, a screenshot, or a GitHub file. Notebooks get shared and saved with their contents, and bots scan public GitHub for keys within minutes. The only place your key should live is the Kaggle Secret you create in step 8. If you ever think a key has leaked, delete it on OpenRouter and make a new one.

    Why OpenRouter?

    OpenRouter is a single account and API that reaches models from many companies (Anthropic, OpenAI, Google, and others). The notebook uses it to call judge models: other language models that read Gemma's responses and score them (see concept 2). These judge models are paid, but very cheap; a full run of the notebook costs cents, not dollars.

    Steps

    1. Go to openrouter.ai and click Sign in. You can use a Google or GitHub account.
    2. Add credit. Open openrouter.ai/settings/credits and buy the smallest amount it offers (around US$5 at the time of writing). The paid judge models refuse requests from an account with no credit, so this step is required.
    3. Create a key. Open openrouter.ai/settings/keys (openrouter.ai/keys redirects there) and click Create API Key. Give it a name you will recognise, such as dataworks-kaggle.
    4. Set a credit limit on the key, for example US$2. A limit caps how much this one key can ever spend, so a leaked or buggy key cannot drain your balance.
    5. Copy the key immediately and keep it somewhere private for the next few minutes (a password manager is ideal). OpenRouter shows the full key only once. If you lose it, delete that key and create a new one; that is normal and costs nothing.

    The notebook needs a way to reach judge models without you running them yourself. Credit is needed because the judges are paid models. The credit limit is a safety net, and copying the key straight away matters because there is no way to view it again later.

    Your key list on OpenRouter shows the new key with its limit, your credit balance is above zero, and you have a string beginning with sk-or-v1- saved privately.

  4. Accept the Gemma 2 license on Kaggle

    1. Open the Gemma 2 model page: kaggle.com/models/google/gemma-2.
    2. Near the top you will see a box saying you need to request access to Gemma 2. Click Request Access.
    3. Read the Gemma terms of use, fill in the short form, and accept.

    Gemma's weights are free to download, but Google releases them under its own license with usage terms. A license gate means the platform will not let your account load the files until you have accepted those terms. Acceptance is tied to your Kaggle account, so you do it once, and it covers every Gemma 2 size (2B, 9B, 27B). Our notebook does not need a HuggingFace account or token, because it loads Gemma from Kaggle's copy.

    The request-access box is gone from the model page. Approval is usually immediate. If the box is still there after a refresh, wait a few minutes and try again.

  5. Import the notebook into Kaggle

    Notebook to import: persona_axis_kaggle_exercises.ipynb (the student version, with exercise stubs to fill in).

    1. Download the notebook file from the link above and save it somewhere you can find it. If your browser opens it as text instead of downloading, right-click the link and choose Save Link As…, and keep the .ipynb ending.
    2. On Kaggle, click Code in the left menu, then New Notebook. An empty notebook opens in the editor.
    3. In the editor's top menu, choose File → Import Notebook.
    4. Upload the .ipynb file you downloaded, then confirm. The empty notebook is replaced with the lab notebook.
    5. Rename it something you will find again, like assistant-axis-yourname, by clicking the title at the top left.

    Importing gives you your own private copy that you can edit and run. Like ARENA's original, each exercise has a collapsible reference solution underneath it. Try the exercise yourself first; that is where the learning happens, and Homework 1 asks you to run the pipeline on personas of your own.

    The notebook shows the lab's title cell and a first code cell with configuration flags such as SMOKE_TEST. Nothing has run yet.

  6. Set the session options: GPU T4 x2 and Internet on

    1. Open the right-hand settings panel in the editor (if it is hidden, click the panel icon at the top right).
    2. Under Session options, set Accelerator to GPU T4 x2. Kaggle may warn that this uses your GPU quota; confirm.
    3. In the same section, turn Internet on.
    4. Leave the other options (language Python, the default environment) as they are.

    Why two GPUs. Each NVIDIA T4 has 16 GB of memory. Gemma 2 9B stored in 16-bit numbers needs about 18 GB for the weights alone, before counting the memory used while the model runs. It does not fit on one T4, but it does fit when Hugging Face's device_map="auto" puts roughly half the layers on each card. The other Kaggle option, a single P100, also has 16 GB and is too small.

    Why Internet. The setup cell downloads ARENA's helper code and clones the paper's repository (which holds the transcripts used in Section 2), and the judge calls go out to OpenRouter.

    The session restarts and the panel shows GPU T4 x2 with Internet on. Once you run any cell, the resource meter at the top shows two GPUs.

    If you pick the wrong accelerator

    With None (CPU only) the notebook either stops with a "no GPU" error or crawls for hours. With GPU P100 or a TPU, loading the 9B model runs out of memory. Fix it by changing the accelerator here; the session restarts, so run the cells again from the top.

  7. Add Gemma 2 as an input

    1. In the right-hand panel, find Input and click Add Input.
    2. Choose the Models filter, search for Gemma 2, and pick the one published by Google.
    3. For Framework, choose Transformers.
    4. For Variation, choose gemma-2-9b-it and add it.
    5. Repeat and also add gemma-2-2b-it (same model, same framework). This small model is what the smoke test uses.

    Why Transformers. Kaggle offers the same Gemma 2 weights in several formats: Transformers, PyTorch, Flax, GGUF, Gemma C++, and TFLite. Only the Transformers format loads with Hugging Face's AutoModelForCausalLM, which is what the notebook uses. That library lets us ask for the hidden states between layers (output_hidden_states=True) and attach hooks to each layer, the two things this whole project depends on. The "PyTorch" option here is Google's own standalone implementation with a different file layout, and GGUF, Gemma C++ and TFLite are compressed formats for fast inference that do not give you those internals.

    Base versus instruction-tuned. Each size comes in two versions. gemma-2-9b is the base (pre-trained) model: it has only learned to continue text. gemma-2-9b-it is instruction-tuned: it went through post-training to follow instructions and act as a chat Assistant. This project is about the Assistant persona that post-training creates, so we need the -it models. A base model has no default Assistant to find.

    The Input panel lists both models. The files appear under /kaggle/input/, in a folder like /kaggle/input/gemma-2/transformers/gemma-2-9b-it/2 (the last number is the model version). The notebook searches /kaggle/input for the right folder itself, so the exact version number does not matter.

  8. Add your OpenRouter key as a Kaggle Secret

    1. In the editor's top menu, open Add-ons → Secrets.
    2. Click Add Secret (or Add a new secret).
    3. For the label, type exactly OPENROUTER_API_KEY: all capitals, underscores, no spaces.
    4. For the value, paste your OpenRouter key. Save.
    5. Make sure the box next to OPENROUTER_API_KEY is ticked. The tick is what attaches the secret to this particular notebook.

    Inside the notebook, a cell reads the secret by its label:

    OPENROUTER_API_KEY = None
try:
    from kaggle_secrets import UserSecretsClient

    OPENROUTER_API_KEY = UserSecretsClient().get_secret("OPENROUTER_API_KEY")
except Exception as e:  # not on Kaggle, or the secret is not attached to this notebook
    print(f"Could not read the Kaggle secret ({type(e).__name__}), falling back to the environment variable")
    OPENROUTER_API_KEY = os.environ.get("OPENROUTER_API_KEY")

assert OPENROUTER_API_KEY, "Add a Kaggle Secret called OPENROUTER_API_KEY (Add-ons -> Secrets) and attach it to this notebook"

    Kaggle Secrets keep the key out of the notebook itself. The value is stored by Kaggle and only handed to your running session, so it never appears in a cell, an output, or a saved version.

    The Secrets dialog lists OPENROUTER_API_KEY with a ticked box. When you run the setup cells, no "secret not found" error appears.

    Secrets do not travel with a notebook

    If you copy a notebook, or someone shares theirs and you click Copy & Edit, the secret is not copied. That is deliberate, so nobody can borrow your key. In every new notebook, open Add-ons → Secrets and tick your existing secret again.

  9. Run the smoke test first, then the full 9B run

    A smoke test is a short, cheap run whose only job is to show that everything is wired up correctly before you spend real time and GPU quota. In our notebook it uses Gemma 2 2B with a handful of personas and questions.

    1. In the first code cell, make sure SMOKE_TEST = True. Leave the other flags at their defaults.
    2. Click Run All (or run cells one at a time with Shift+Enter to watch each step).
    3. Wait. The setup cell installs a few packages, downloads ARENA's helper code, and clones the paper's repository (about a minute). Then the 2B model loads (about a minute), and Section 1 and Section 2 run (several more minutes).

    The configuration cell has these flags:

    FlagDefaultWhat it does
    SMOKE_TESTTrueGemma 2 2B, 10 personas, 2 questions. Set to False for the real run with 9B.
    USE_FULL_PERSONA_LISTFalseAll 275 roles from the paper, all 15 questions, and 256-token responses. Takes hours; not for homework.
    GENERATION_BACKEND"local"Where persona responses come from. "local" uses the loaded Gemma. "openrouter" asks Gemma 2 27B through the API instead.
    RUN_JUDGE_FILTERFalseScores every persona response with the Claude Haiku judge and keeps only fully in-character ones, as the paper does. Adds a little API cost and a few minutes.

    The model-loading cell prints Loading gemma-2-2b-it from /kaggle/input/…, then NUM_LAYERS=26, D_MODEL=2304, EXTRACTION_LAYER=17. The float16 check prints "No NaN or inf in logits or hidden states." The persona cell prints "Using 10 personas", and the generation cell prints short answers to "What is your name?" from the ghost, the jester and the assistant (the ghost should sound like a ghost). That output is your smoke test passing.

    Run All then stops at the first exercise, the judge prompt, with NotImplementedError. That is expected: the rest of the notebook needs your answers to the exercises. Once you have done them, running further gives a cosine-similarity heatmap, a PCA scatter plot, the paper's 27B reference plots, drift plots, and steering outputs. With only 10 personas and 2 questions the smoke-test plots are noisy; it checks the plumbing, not the science.

    Switching to the full 9B run

    1. Set SMOKE_TEST = False in the first cell.
    2. Restart the session so the 2B model is cleared from GPU memory: Run → Restart & clear cell outputs (or the restart button in the toolbar).
    3. Run all cells again. Loading 9B takes 3 to 5 minutes. Section 1 then takes about 10 minutes (generating the 265 responses is most of it), and Section 2 another 5 to 10. These are estimates; the 9B run has not been timed on Kaggle yet.

    Results are cached in /kaggle/working/persona_cache/, so if a later cell fails you can fix it and re-run without regenerating everything that already finished.

  10. Understand your GPU quota

    Kaggle gives each verified account a weekly allowance of GPU hours. The figure most users see is around 30 hours per week, but Kaggle can change it and does not promise a fixed number in its documentation, so check your own. To see it, click your profile picture → Settings and look for the quota section, or look at the quota meter in the right-hand panel of the notebook editor. The weekly allowance resets once a week.

    • Quota is used while a GPU session is running, not only while a cell is executing. A GPU notebook sitting open in a tab while you read is still spending your hours.
    • Stop the session when you are done: click the power icon in the top bar of the editor, or Run → Stop session. You can also see and stop any running sessions under View Active Events in the left menu.
    • Kaggle ends an interactive session on its own after about 20 minutes with no activity, and any single session after 12 hours. Do not rely on that to save quota.

    Two T4s for a full run plus a few re-runs comes to a few hours a week, well within the allowance, but forgetting a session overnight can use up a third of your week.

  11. Save your work

    The notebook writes its results (responses, persona vectors, scores) under /kaggle/working. During an interactive session, everything in /kaggle/working is lost when the session ends, whether you stop it, it times out, or you close the tab and it idles out.

    To keep your code and outputs, click Save Version at the top right. You get two choices:

    • Quick Save takes a snapshot of the notebook exactly as it looks now: your code and the outputs currently shown in cells (plots and printed results). It does not re-run anything. Use it often.
    • Save & Run All (Commit) starts a fresh session, runs the whole notebook top to bottom, and keeps the files it writes to /kaggle/working (up to 20 GB) as the version's Output. This uses GPU quota for the whole run, so use it when you want a clean, complete record, for example before submitting homework.

    A saved version's output files can be attached as an input to a later session (Add Input → your notebook), which lets you reuse cached responses and vectors instead of recomputing them.

    Your notebook's page lists a version number, and opening the version shows your plots. For a Save & Run All version, its Output tab lists the files from /kaggle/working.

Troubleshooting

Find the message closest to what you see. If nothing here helps, post the full error (with any key blurred) in the group channel.

torch.OutOfMemoryError: CUDA out of memory

The GPUs ran out of memory. Check, in order:

  1. The accelerator is GPU T4 x2, not P100 (step 6).
  2. You restarted the session after switching from the 2B smoke test to 9B. Two models loaded at once will not fit.
  3. If it happens during response generation, lower GEN_BATCH_SIZE in the generation cell (try halving it).
  4. If it happens while analysing a transcript in Section 2, lower MAX_DRIFT_TURNS (6 by default) so fewer turns go through the model at once.

After an out-of-memory error, restart the session before trying again; the memory often stays fragmented.

AssertionError: Non-finite values in [...] with dtype=torch.float16. Gemma 2 overflowed in float16. (or NaN outputs, empty strings, repeated <pad> tokens)

T4 GPUs do not support bfloat16 natively, so on Kaggle the model runs in float16. That format has a much smaller range, and Gemma 2's activations can grow large enough to overflow it, which turns numbers into inf and then NaN. The symptom is a heatmap full of blanks, a PCA error about NaN, or generations that are empty or garbage.

The cell right after loading, check_fp16_numerics, catches this before anything else runs, and stops with the message above. The fix is to load the model in 8-bit with the bitsandbytes library, which keeps the numbers in a safe range at some cost in speed and uses about half the memory:

  1. In a new cell, run %pip install -q bitsandbytes.
  2. In the model-loading cell, replace the model = AutoModelForCausalLM.from_pretrained(...) call with the commented-out 8-bit version just below it (uncomment those lines).
  3. Restart the session and run from the top.
AssertionError: Add a Kaggle Secret called OPENROUTER_API_KEY (Add-ons -> Secrets) and attach it to this notebook

The notebook could not read your key; just above the error it prints "Could not read the Kaggle secret". Usually one of:

  • The label is not exactly OPENROUTER_API_KEY (check for a lowercase letter, a space, or a typo).
  • The secret exists but its box is not ticked for this notebook. Open Add-ons → Secrets and tick it.
  • This is a copied notebook, and secrets do not carry over. Tick the secret again in this copy.

After fixing it, re-run the cell that loads the secret.

FileNotFoundError: No gemma-2-9b-it model found under /kaggle/input. Add the Kaggle Model 'Gemma 2' (framework Transformers, variant gemma-2-9b-it) as an input.

The model files are not attached, or the wrong format was attached. The error ends with the list of model folders that are attached, which usually shows the problem straight away.

  • Check the Input panel: you need Gemma 2, framework Transformers, variation gemma-2-9b-it (and gemma-2-2b-it for the smoke test). If you picked PyTorch, Flax, or GGUF, remove it and add the Transformers one.
  • If the smoke test is on, the 2B variation must be attached; with it off, 9B must be.
  • Run !ls -R /kaggle/input | head -50 in a new cell to see what is actually there.
  • If adding the model fails with an access message, you have not accepted the Gemma license yet (step 4).
Internet is off: pip install fails, "Temporary failure in name resolution", or git clone fails

The setup cell needs Internet to install packages, download ARENA's helper code, and clone the assistant-axis repository. Turn Internet on in Session options. If the switch is greyed out, your phone is not verified yet (step 2). After turning it on, re-run the setup cell.

OpenRouter 401 Unauthorized ("No auth credentials found" or invalid key)

OpenRouter did not accept the key. The key was mistyped or pasted with extra spaces, was deleted, or was disabled. Create a new key, update the value of the Kaggle Secret, and restart the session so the new value is picked up.

OpenRouter 402 Payment Required (insufficient credits)

Your account, or this key's credit limit, has no credit left. Check your balance on the Credits page and the key's limit on the Keys page. Add credit or raise the limit, then retry. Before you do, make sure nothing is looping and making calls you did not expect.

OpenRouter 429 Too Many Requests (rate limited)

You sent requests faster than OpenRouter or the model provider allows. The notebook sends judge calls in parallel. Lower MAX_WORKERS (try 2 to 4) and run the cell again. Waiting a minute also helps. Cached results mean finished calls are not repeated.

OpenRouter 404 or "No endpoints found" for a model name

The judge model named in the notebook is no longer offered on OpenRouter. Models are retired from time to time (for example, the Claude 3.5 Haiku judge used by the original ARENA notebook has been removed). Check the model name against openrouter.ai/models and tell a leader. The fix belongs in the notebook so everyone gets it.

The session restarted or disconnected and my variables are gone

Kaggle ends an interactive session after about 20 minutes without activity. Re-run from the top. Thanks to the cache in /kaggle/working/persona_cache/, finished steps are fast as long as the same session's files are still there. If the session fully ended, those files are gone too unless you saved a version (step 11).
