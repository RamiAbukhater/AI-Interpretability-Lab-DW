Persona vectors and cosine similarity

You now have one 3584-dimensional vector per persona. The first question to ask is simple: which personas does the model treat as similar? This page covers the tool for that, cosine similarity, and the one-line fix (mean-centering) without which the answer is useless.

The big idea

Two vectors can be compared by the angle between them. If they point the same way they are similar, if they are at right angles they share nothing, and if they point in opposite directions they are opposites. Cosine similarity is the cosine of that angle:

\[ \cos(u, v) = \frac{u \cdot v}{\lVert u \rVert\,\lVert v \rVert} \in [-1, 1]. \]

It ignores length and looks only at direction. That suits activations, where the overall size of a vector varies for boring reasons (longer responses, some tokens being louder) but the direction carries meaning.

There is a catch, and the notebook makes you hit it on purpose. Every activation in a model contains a large shared component: a "this is a Gemma residual stream at layer 27" offset that is the same no matter what the text is about. Persona vectors are averages of thousands of activations, so that shared part dominates. Compare two of them and you are mostly comparing the shared part with itself, and every pair scores close to 1.0. It is like comparing the heights of people standing on a 100 m tower: everyone is about 101.7 m tall, and the differences you care about are lost.

The fix is mean-centering: subtract the average of all persona vectors from each one, then compare.

\[ \bar v = \frac{1}{P}\sum_{p=1}^{P} v_p, \qquad \tilde v_p = v_p - \bar v. \]

Now each \(\tilde v_p\) says how persona \(p\) differs from the typical persona, and cosine similarity between the centered vectors shows real structure: Assistant-like personas point one way, fantastical ones point another.

Diagram

Reading the heatmap

The notebook draws the full matrix of pairwise similarities as a heatmap: personas along both axes, one coloured cell per pair, blue for positive and red for negative, white at zero.

  • The diagonal is always 1: every persona is identical to itself.
  • The matrix is symmetric: the cell for (ghost, oracle) equals (oracle, ghost).
  • Look for blocks. If the default and Assistant-like personas form a blue square with each other, and the fantastical ones form another blue square, while the cells between the two groups are red, the model separates those groups. That is the first hint of a single dominant direction.
  • The uncentered heatmap will look almost entirely one colour (all near 1). That is the problem above, not a result.

How it connects to the paper

  • Section 2.1.3: before analysing persona space, the paper standardises role vectors by subtracting the mean vector across roles, which is the same centering step.
  • Section 3.1 and the paper's visualize_axis.ipynb notebook rank roles and traits by cosine similarity with the Assistant Axis. You will do a smaller version of that ranking on the next page.
  • The "everything has cosine near 1" effect is a well-known trap in interpretability. Neel Nanda's Mech Interp Puzzle 1 is the same phenomenon in GPT-Neo's embeddings.

What it must do: compute the cosine similarity between every pair of persona vectors at once, and return the names in the same order as the rows.

StepShape

Hint 1

If every row has length 1, the dot product of two rows is their cosine similarity. So normalise once, then one matrix multiplication computes all pairs.

Hint 2

vectors.norm(dim=1, keepdim=True) keeps the shape (n, 1) so that dividing broadcasts across each row. @ and .T do the rest.

Hint 3

Build the name list first with list(persona_vectors.keys()) and stack in that order, so row \(i\) and name \(i\) always match.

Run it and plot the result. You should see the "everything is about 1" problem. The notebook then gives you the centered version, which is your function plus one line:

def compute_cosine_similarity_matrix_centered(persona_vectors):
    names = list(persona_vectors.keys())

    # Stack vectors into matrix and center by subtracting mean
    vectors = t.stack([persona_vectors[name] for name in names])
    vectors = vectors - vectors.mean(dim=0)

    # Normalize
    vectors_norm = vectors / vectors.norm(dim=1, keepdim=True)

    # Compute cosine similarity
    cos_sim = vectors_norm @ vectors_norm.T

    return cos_sim, names


cos_sim_matrix_centered, persona_names = compute_cosine_similarity_matrix_centered(persona_vectors)

px.imshow(
    cos_sim_matrix_centered.float(),
    x=persona_names, y=persona_names,
    title="Persona Cosine Similarity Matrix (Centered)",
    color_continuous_scale="RdBu",
    color_continuous_midpoint=0.0,
).show()
  • t.stack(...): list of (d_model,) tensors → (n, d_model).
  • vectors.mean(dim=0): average over personas → (d_model,), the vector \(\bar v\). Subtracting it broadcasts across all rows. This is the one-line fix.
  • Normalise each row, then vectors_norm @ vectors_norm.T: (n, d_model) × (d_model, n) → (n, n).
  • .float() before plotting: the model's half-precision tensors are converted to 32-bit floats, which plotting libraries expect.
  • color_continuous_midpoint=0.0 pins white to zero so blue always means similar and red always means opposite.

Keep this centered heatmap. It helps when you interpret where your own two personas land in Homework 1, Part C.

Check your understanding

Q1.Without centering, why do almost all pairs have cosine similarity close to 1?

All persona vectors contain a large shared component (the average activation at that layer). When that component is much bigger than the persona-specific differences, every vector points in nearly the same direction, so every angle is small and every cosine is near 1.

Q2.After centering, can a pair of personas have negative cosine similarity? What does it mean?

Yes. Centered vectors describe how each persona differs from the average persona. A negative cosine means two personas differ from the average in opposite directions, for example the default Assistant and the jester.

Q3.Does centering depend on which personas you include?

Yes. \(\bar v\) is the mean of the personas you have. Add ten more fantastical personas and the mean moves toward them, which changes every centered vector and every similarity. Compare heatmaps only when they use the same persona set.

Q4.Why use cosine similarity rather than the plain dot product?

The dot product grows with vector length, and activation lengths vary for reasons unrelated to the persona (for example response length or a few unusually large dimensions). Cosine similarity divides out length and compares direction only.

Common mistakes

  • Interpreting the uncentered heatmap. It shows the shared offset, not persona structure.
  • Normalising along the wrong dimension (dim=0 instead of dim=1), which normalises each feature across personas instead of each persona vector. The diagonal will not be all ones, which is an easy check.
  • Forgetting keepdim=True, so the division tries to broadcast (n,) against (n, d_model) and fails or divides the wrong axis.
  • Losing track of the name order. Iterating over the dict twice in different ways can mislabel the heatmap. Build the names once and reuse them.
  • Mixing devices or dtypes. If some vectors are on the GPU in float16 and others on CPU in float32, t.stack fails. Move them all to CPU float32 first.
