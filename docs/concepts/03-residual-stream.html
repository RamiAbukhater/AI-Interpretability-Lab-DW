The residual stream and extracting activations

This is where we stop treating the model as a black box. We run each in-character response back through Gemma, read the model's internal state at one layer, and compress it into a single vector per persona.

The big idea

A transformer turns each token of the input into a vector of numbers and then passes that vector up through a stack of layers (Gemma 2 9B has 42). The vector that travels up through the stack is called the residual stream. Each layer reads the current vector, computes something (an attention step that looks at other tokens, then an MLP step), and adds its result back onto the vector. Nothing is overwritten; information accumulates. At the top, the final vector is turned into a prediction for the next token.

A good mental model is a shared whiteboard that travels with each token. Every layer can read the whole board and write a few notes onto it. The board at layer 27 holds everything the model has worked out about that token by that point, including, we hope, which character it is currently playing. The board's contents at a given layer are called the hidden state or activation at that layer. For Gemma 2 9B each one is a vector with \(d_\text{model} = 3584\) numbers (2304 for the 2B smoke-test model).

Which layer should we read? Early layers mostly hold information about the literal token and its spelling or grammar. The last few layers are busy turning everything into a specific next-word prediction. The middle-to-late layers are where models tend to represent abstract things: topic, tone, intent, and character. The notebook reads at 65% of the depth: layer 27 of 42 for 9B, layer 17 of 26 for 2B.

Finally, a response is many tokens long and each token has its own hidden state. To get one number-vector per persona, we average: first over the tokens of each response (only the response, not the system prompt or question), then over all of that persona's responses. Averaging washes out what is specific to individual words and questions, and keeps what is common to everything the persona said: the persona itself.

Diagram

In symbols, if response \(r\) has response tokens \(T_r\) and \(h_t^{(\ell)}\) is the hidden state of token \(t\) at layer \(\ell\), the notebook computes

\[ a_r = \frac{1}{|T_r|}\sum_{t \in T_r} h_t^{(\ell)}, \qquad v_p = \frac{1}{|R_p|} \sum_{r \in R_p} a_r , \]

where \(R_p\) is the set of (kept) responses for persona \(p\). The vector \(v_p \in \mathbb{R}^{d_\text{model}}\) is that persona's persona vector.

How it connects to the paper

  • Section 2.1.2: the paper's role vectors are the mean post-MLP residual stream activation over all response tokens, from the middle layer of the model unless stated otherwise. That is exactly the averaging above.
  • Layer choice. The paper uses the middle layer (for Gemma 2 27B, its released configuration uses layer 22 of 46). ARENA chose 65% of the depth so that its later sections line up with the layers Google's GemmaScope sparse autoencoders were trained on, and our notebook keeps 65%. Both are in the middle-to-late band where abstract features live. Trying other layers is a good extension.
  • Section 3.1 computes the axis at every layer and finds it is most aligned with the main direction of persona space around the middle layers.

Right after loading, check_fp16_numerics(model, tokenizer) runs one forward pass and checks that every layer's hidden states and the logits are finite. It prints the largest activation it saw next to the float16 maximum of 65504. If anything overflowed it stops with "Non-finite values in … Gemma 2 overflowed in float16", and tells you to reload in 8-bit using the commented-out lines in the loading cell (see troubleshooting).

Finding the blocks, and which "layer" we mean

def _return_layers(m) -> list:
    """Walk model attributes to locate the list of transformer blocks."""
    for attr_path in ("language_model.layers", "layers"):
        obj = m.model
        try:
            for name in attr_path.split("."):
                obj = getattr(obj, name)
            return obj
        except AttributeError:
            continue
    raise AttributeError(f"Could not find transformer layers on {type(m)}")


def _get_hidden(output) -> Tensor:
    """Hidden states from a decoder block's forward-hook output (a tensor in recent transformers, a tuple in older ones)."""
    return output[0] if isinstance(output, tuple) else output
  • _return_layers(model) returns the list of transformer blocks, model.model.layers for Gemma 2, so _return_layers(model)[27] is block 27.
  • Layer convention. Throughout the notebook, "layer L" means the output of block L, read with a forward hook (concept 6 explains hooks). Section 1 extracts persona vectors there and Section 2 monitors and steers at the same place.
  • _get_hidden exists because, depending on the transformers version, a block's hook receives either the hidden-states tensor or a tuple whose first element is that tensor.

Formatting a conversation and finding where the response starts

def _normalize_messages(messages):
    """Merge any leading system message into the first user message."""
    if not messages or messages[0]["role"] != "system":
        return messages
    system_content = messages[0]["content"]
    rest = list(messages[1:])
    if rest and rest[0]["role"] == "user" and system_content:
        rest[0] = {"role": "user", "content": f"{system_content}\n\n{rest[0]['content']}"}
    return rest


def format_messages(messages, tokenizer) -> tuple[str, int]:
    messages = _normalize_messages(messages)
    full_prompt = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=False)
    prompt_without_response = tokenizer.apply_chat_template(
        messages[:-1], tokenize=False, add_generation_prompt=True
    ).rstrip()
    response_start_idx = (
        tokenizer(prompt_without_response, return_tensors="pt", add_special_tokens=False).input_ids.shape[1] + 1
    )
    return full_prompt, response_start_idx
  1. _normalize_messages (defined in the generation cell): Gemma 2 has no system role, so the persona prompt is glued in front of the user's question.
  2. apply_chat_template wraps the conversation in Gemma's special markers, roughly <bos><start_of_turn>user … <end_of_turn><start_of_turn>model …. full_prompt includes the response.
  3. prompt_without_response is the same conversation without the last (assistant) message, but with add_generation_prompt=True, which appends the "model's turn starts here" marker. Counting its tokens tells us where the response begins.
  4. The + 1 skips the newline token after the turn marker, which the .rstrip() removed from the string.
  5. add_special_tokens=False: the chat template already contains <bos>. Letting the tokenizer add a second one would shift every position by one.

What it must do: for each (system prompt, question, response) triple, run the full conversation through the model once, capture the output of block layer, average it over the response tokens only, and return all the averages stacked, on the CPU in float32.

Hint 1: capturing one block

The notebook recommends a forward hook on _return_layers(model)[layer] that stores _get_hidden(output) in a dictionary. Register it once before the loop and remove it in a finally block. Then a plain model(**tokens) inside t.inference_mode() fills the dictionary. (output_hidden_states=True also works for short sequences, but it keeps every layer in memory, and block layer's output is then outputs.hidden_states[layer + 1].)

Hint 2: building the conversation

Make a three-message list (system, user, assistant) and pass it to format_messages. Tokenize the returned string with add_special_tokens=False and move it to model.device.

Hint 3: averaging only the response

Either slice from response_start_idx to the end and take .mean(0), or build a boolean mask with t.arange(seq_len) >= response_start_idx and divide the masked sum by the mask's sum. Do the mean in float32 (.float()) and move each result to the CPU before stacking, so you do not keep many GPU tensors alive and every persona vector ends up in the same dtype.

Check your understanding

Q1.What is the shape of one persona vector for Gemma 2 9B, and why that size?

(3584,). It is a single residual-stream vector, and Gemma 2 9B's residual stream has \(d_\text{model} = 3584\) dimensions. Averaging over tokens and responses removes the token and example dimensions.

Q2.Why average only over response tokens and not the whole sequence?

The prompt tokens include the persona instruction itself ("You are a ghost…"). Their activations would mostly encode the words of the instruction, not the model acting as the character. The response is where the model is actually in character. It also matches the paper's method.

Q3.Why read a middle-to-late layer rather than the last layer?

The final layers are specialised for predicting the exact next token, so their activations are dominated by word-level detail. Middle-to-late layers tend to hold more abstract features like style, topic and role, which is what we want to compare.

Q4.If you forgot add_special_tokens=False when tokenizing, what would go wrong?

The sequence would start with two <bos> tokens, so every position would be shifted by one relative to response_start_idx. The average would include the last prompt token and miss the last response token. Small, but it is the kind of quiet bug that corrupts results.

Q5.If you used output_hidden_states=True instead of a hook, which index of outputs.hidden_states matches the notebook's "layer 27"?

Index 28. Index 0 is the embedding output, so index \(i\) is the output of block \(i-1\). The notebook's "layer 27" is the output of block 27, which is what a hook on _return_layers(model)[27] captures. (The original ARENA notebook mixed these up: Section 1 read hidden_states[27] while Section 2 steered block 27. Our notebook uses block 27 everywhere.)

Common mistakes

  • Averaging the prompt tokens too, by forgetting the response mask. Persona vectors then mostly reflect the instruction text.
  • A double <bos> from tokenizing without add_special_tokens=False, which shifts the response mask by one.
  • Out-of-memory from keeping tensors on the GPU. Move each mean to CPU before appending, use inference_mode, and keep the t.cuda.empty_cache() between personas.
  • Off-by-one on layer indices. If you use output_hidden_states=True, remember it has NUM_LAYERS + 1 entries, and block L is hidden_states[L + 1]. Reading hidden_states[L] would give you a different layer from the one Section 2 steers.
  • Forgetting to remove the hook. Use try / finally; a leftover hook keeps capturing on every later forward pass.
  • Using a stale cache. The vector file name includes the layer (_L27), but responses are shared across layers. If you change prompts, delete both responses.json and the vector file.
