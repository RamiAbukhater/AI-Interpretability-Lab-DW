Steering along the Assistant Axis

So far we have only watched the axis. Now we push on it. By adding the axis vector into the residual stream while the model writes, we can make it more or less Assistant-like, and that is the strongest evidence that the axis is something the model actually uses.

The big idea

Everything up to now has been descriptive. We found a direction that separates Assistant-like personas from the rest, and showed that it tracks drift in conversations. But a direction can correlate with something without the model using it, the way a thermometer tracks the weather without causing it. To show the direction is causal, we intervene: change the model's activations along that direction and see whether its behaviour changes the way we predict.

Activation steering does this with a forward hook (concept 6) that, instead of just reading the residual stream at one layer, adds a vector to it at every token position:

\[ h^{(\ell)} \;\leftarrow\; h^{(\ell)} + \alpha\, s , \]

where \(h^{(\ell)}\) is the hidden state at layer \(\ell\), \(s\) is the steering vector, and \(\alpha\) is a coefficient we choose. Every layer above \(\ell\) then reads the nudged vector, as if the model had "thought" more (or less) Assistant-like thoughts at that point.

The sign and size of \(\alpha\) are the experiment:

  • \(\alpha = 0\): no change, the baseline.
  • \(\alpha > 0\): pushed toward the Assistant. Answers become more grounded and professional, and the model resists or drops role-play prompts.
  • \(\alpha < 0\): pushed away. The model adopts personas more readily, makes up names and backstories, and at larger magnitudes slides into mystical, theatrical prose.
  • Very large \(|\alpha|\): the vector swamps the original activation and the text falls apart into repetition or nonsense. The useful range is where the effect is clear but the text is still coherent.

To make \(\alpha\) interpretable, the notebook scales the unit axis \(a\) by the persona gap: the distance along the axis between the average default persona and the average role persona.

\[ \text{AXIS\_SCALE} = \frac{1}{|D|}\sum_{p\in D} v_p\cdot a \;-\; \frac{1}{|R|}\sum_{p\in R} v_p\cdot a, \qquad s = \text{AXIS\_SCALE}\cdot a . \]

So \(\alpha = -1\) means "move the activation one full Assistant-to-role gap away from the Assistant". The notebook suggests trying values between ±1 and ±5.

Scaling the axis into persona-gap units

assistant_axis = F.normalize(assistant_axis.cpu().float(), dim=0)

_default_projs = (
    t.stack([persona_vectors[n].cpu().float() for n in DEFAULT_PERSONAS if n in persona_vectors]) @ assistant_axis
)
_role_names = [n for n in persona_vectors if n not in DEFAULT_PERSONAS]
_role_projs = t.stack([persona_vectors[n].cpu().float() for n in _role_names]) @ assistant_axis
AXIS_SCALE = float((_default_projs.mean() - _role_projs.mean()).item())
axis_steer = assistant_axis * AXIS_SCALE  # Scaled vector for steering (not unit-norm)
  • F.normalize makes sure the axis has length exactly 1, in CPU float32 for clean arithmetic.
  • _default_projs: (n_default, d_model) @ (d_model,) → (n_default,), the position of each default persona along the axis. Same for _role_projs.
  • AXIS_SCALE is the gap between the two group means, a positive number. axis_steer is the axis stretched to that length, so adding 1.0 * axis_steer moves a vector by one gap.

What it must do: generate a reply to prompt (with an optional persona system_prompt, or a full messages list for multi-turn) while a hook adds alpha * steering_vector to the output of block steering_layer at every position, and return only the newly generated text.

Hint 1: building the prompt

If messages is not given, build it from system_prompt (if any) and prompt. Run it through _normalize_messages (Gemma has no system role), then apply_chat_template(..., add_generation_prompt=True), and tokenize with add_special_tokens=False. Remember the prompt length.

Hint 2: the hook

Inside the hook, add alpha * steering_vector to the output, cast to the output's device and dtype (the two GPUs and half precision both matter), and return the result. Because the vector has shape (d_model,), broadcasting applies it to every position, during the prefill and every generation step.

Hint 3: generating

Register the hook on _return_layers(model)[steering_layer], call model.generate with do_sample=True and your temperature inside try, and remove the hook in finally. Decode only the tokens after the prompt, with skip_special_tokens=True.

Steering experiments

The last exercise is open-ended: there is no function to fill in, you design the comparison. The notebook asks for two experiments.

  1. Symmetric steering. Choose three personas: one Assistant-like (consultant), one mid-range (philosopher), one fantastical (ghost). Ask each the same question (for example "How can I take steps to add meaning to my life?") at several values of \(\alpha\), such as \(-5, -2, 0, 2, 5\). Lay the outputs side by side.
  2. Role adoption. Use prompts like "You are a secretary. What is your name?" At what \(\alpha\) does the model start inventing a human name and backstory instead of saying it is an AI?

First find a useful range on one prompt: too small and nothing changes, too large and the output is gibberish. Use the same random seed or several samples per setting, since generation is random at temperature 0.7.

These outputs are what you submit in Homework 3.

Why this shows the axis is causal

The monitoring results on the previous page are correlations: the projection falls when behaviour gets worse. That alone could mean the axis merely reflects some other process. Steering is an intervention. We change only one thing, the component of the activation along \(a\), and behaviour moves in the direction the axis predicts: away from the Assistant gives more role adoption, toward it gives less. The model's later layers are clearly reading and using this direction.

A careful experiment needs a control: steer along a random direction scaled to the same length. If a random vector of the same size gives the same changes, the effect is just "adding noise breaks things", not a property of the axis. This is a good extension to propose.

Check your understanding

Q1.What does \(\alpha = -2\) mean in this notebook?

Add \(-2 \times\) axis_steer to the residual stream at the steering layer: shift every token's activation two persona gaps away from the Assistant end of the axis.

Q2.Why steer every position, including the prompt, instead of only newly generated tokens?

During the first pass the model computes and caches keys and values for every prompt token. Steering those positions changes how the model has "understood" the whole context, including the persona instruction, which gives a much stronger effect than nudging only the new tokens. After the prefill, the cache means each new token is steered as it is produced.

Q3.Why does monitoring alone not prove the model uses the axis, and how does steering help?

Monitoring shows correlation: the projection changes along with behaviour. Steering is an intervention: we change the activation along the axis and observe behaviour change in the predicted direction, which shows the model's downstream computation depends on that direction.

Q4.What control experiment would strengthen the claim, and what result would weaken it?

Steer along a random direction with the same norm as \(\alpha\,s\). If random directions produce similar persona shifts, the effect is generic disruption rather than something specific to the Assistant Axis.

Q5.Why might large positive \(\alpha\) also make outputs worse?

Adding a very large vector pushes activations far outside the range the model ever saw in training. Later layers no longer get inputs they know how to process, so text degrades no matter which direction you push.

Common mistakes

  • Leaving the steering hook attached. Every later generation is silently steered. Always remove it in finally; if outputs look strange later, restart the session.
  • Device or dtype mismatch: the model is split over two GPUs and runs in half precision, so steering_vector must be moved to the output's device and dtype inside the hook.
  • Returning the prompt with the reply. Slice off the first prompt_length tokens before decoding.
  • Using the unit axis instead of axis_steer. A unit vector is tiny compared with the activation norm, so nothing seems to happen at \(\alpha = 5\).
  • Judging from one sample. Generation is random; compare several samples per \(\alpha\), or fix the seed.
  • Getting the sign backwards: if positive \(\alpha\) makes the ghost more ghostly, your axis was built the wrong way round (\(\mu_\text{roles} - \mu_\text{default}\)).
